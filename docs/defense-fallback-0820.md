# 0.8.20防御兜底抵消修复与验证

基准0.8.19提交`4d7f0e9`，当前改动只涉及普通工房的防御收尾校验、自动重选及求解继续处理；游戏数据、概率样本、观星位置加权、无扣后补回和第一阶段权重保持不变。

## 判定口径

有兜底时，把兜底与自由段分开。自由段按用户约定先累计全部负防御，再搜索正防御的排列，要求每次加入正防御后均不归零；同时最终含兜底的防御和也不能为0。没有防御记录允许。此为保留记录的简化顺序检查，不完整重放随机抽选、途中预算和失败记录，不证明种子可达性；模拟器仍按实际抽选顺序抵消，真实库存不改写。

六条自由记录若包含`−3、−3、＋6、＋6`以及其他两条非防御，先累计−6后任意第一个＋6都会归零。若改为`−3、−3、＋6、＋4`，可以先＋4得到−2，再＋6得到＋4，不能仅因存在零和子集就拒绝。兜底的合法条目和预算档位仍单独检查；有明确标记时严格使用标记，未标记时检查是否存在合法收尾解释。

正防御排列用位掩码记忆化搜索。自由段最多六条，混合正负防御时最多五条正防御，因此最多32个正防御子集状态。自动重选和补防御的状态还保留正防御值的组成，不能只按净和合并，以免把顺序性质不同的组合混成同一个状态。

自动生成优先重选同ID、同cost、同记录数量的合法值，既有固定炼化不自动改值。无法修复时只排除具体构型并继续搜索；完整七条模型区分净和为0的线性约束与需要具体构型排除的顺序失败，避免反复搜到同一个非法解。

## 性能对照

同机Node，顺序独立运行同一套弓、60秒/30候选，只切换engine模块。单次完整搜索对照，计时存在正常波动；不是任意设备的耗时保证。

| 项目 | 0.8.19 | 修复后 |
|---|---:|---:|
| 完整搜索 | 10.37秒 | 10.90秒 |
| 首条结果 | 1.46秒 | 1.87秒 |
| 最佳等价期望 | 21,661.68 | 21,661.68 |

两边均生成1,341个能力候选、进行238次邻域调整，最佳等价期望相同；单路线预算截断均为0。该固定配置未见明显拖慢，不代表所有目标的搜索轨迹不变。

微基准先预热、旧新交错各7轮取中位数，使用相同合法输入：

- 单件完整校验：0.0655ms → 0.0798ms。
- 自动收尾：0.1041ms → 0.0973ms；微小下降按运行波动理解。

## 回归覆盖

新回归包含手填与固定校验、普通JSON和紧凑分享数据导入、重复DEF计数、无DEF自由段、显式和隐式兜底归属、自动重选、资源模板、不可修复构型排除、完整七条模型继续求解及热启动。针对六条内部的两个用户示例分别检查；另将5,532种混合防御组合与独立的正防御全排列枚举逐项对照。

原始数据及复现脚本在Git仓库`benchmarks/release-0820/`，新增回归在`tests/fallback-before-defense.test.cjs`。完整测试还会验证离线嵌入Worker及下载分片重建。
