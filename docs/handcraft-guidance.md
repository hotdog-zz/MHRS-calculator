# 手炼指导

手炼指导与配装工房共享01～03条件，读取“我的装备箱”中已导入的当前快照。默认使用实际库存护石。03明确指定的合法护石可作为计算前提：库存有技能与孔位匹配的护石时优先引用已有实例；没有匹配时使用指定护石并标记库存未拥有，不自动生成其他理论护石。固定防具炼化仍须在库存存在。

每条路线默认收起，以紧凑表格显示预计次数、待炼部件的技能／孔位要求和所用护石，点击“展开详情”查看完整装备、概率与珠子插法。可选择最多展示5、10、20或50条路线，实际数量取决于时限内找到的结果。

## 路线怎样计算

先用实际成品和护石、数量内的珠子尝试配装。找到时，防具炼化次数为0；若所用护石库存未拥有，会提示另行准备，不能将这条路线视为整套已经拥有。允许制作时也会检查原生防具是否已足够，明确标记需要制作的部件；这类部件没有炼化次数。

需要炼化时，先生成少量起始骨架，再提取充分的技能等级下限和所需孔位。只要求已分配珠子实际需要的孔位等级，不要求把空孔一并炼出来。整套溢出技能只分配一次，避免多个部位同时扣减同一份富余技能后使总目标失效。候选规模30／60／90／120控制后续探索广度，默认30；它不是必须先生成同样数量的整套骨架才开始查概率。

每个目标保留普通、技能特化和插槽特化下所有可用概率。用户禁止删技能或设置逐件新增正面词条上限时，这些限制也进入概率查询。已有成品直接按实际值使用，不由03重新改写。全库存和原生防具的零炼化检查仍然优先执行。

起始骨架最多8套、最多使用剩余时限的20%且不超过8秒。手写权重（待炼部件30、新增技能cost加5、删技能0.05、扩孔等级）只在这个小阶段提供种子。随后选取等效较高的防具，以及具有无珠子替代技能的代表防具，查询“原生能力＋单项技能／扩孔”的独立候选。这样可以更换原生技能布局，不受第一套骨架分配方式限制。

## 当前观星炼化组与等价观星炼化组

此步骤在原有搜索完成后运行。`dist/handcraft.js`的候选生成、概率定价、目标函数、搜索时限、邻域和去重保持原样；`dist/stargazing.js`仅对已经生成的完整路线进行后处理。搜索期间卡片标记观星待评估，结束后逐条替换完成值。停止会保留已显示结果；尚未完成后处理的路线仍标为待评估。

逐件次数继续使用实际目标防具的原有概率表，各自取概率最高的方式后计算次数之和。实际防具表的所有计数保持原样，宫殿护腿原有200万次表也保留供逐件计算。新增的观星专用表在原有前缀上继续到每种方式1,000万次，索引放在`index.observation`，与主表分开加载。它只服务观星，不进入能力候选的概率定价。

pool6的当前组统一使用公会宫殿护腿（Leg:426）的新增技能、原始扩孔、可扣原生技能总级数、记录数及03正面上限查表概率；不把目标防具的最终孔位如4-4-2直接套在宫殿护腿上。原生技能保留下限换算为可扣总级数，不计算具体删技能ID在嫁接时的映射。它是统一来源的概率代理，并非逐条嫁接合法性的证明；界面保留实际防具概率供比较。非pool6仍按实际防具独立最优方式计算，不与pool6共享。

**当前观星炼化组**按实际成果份数计算，固定本条路线的技能分配。需要两件“业铠＋1”就必须取得两份成果；不再将两个部位标签当成两种独立成果。相同新增技能在不同孔位、可扣等级与03限制下只计算一次命中，并保留它能够用于哪些部位。

当前组与等价组共用下文的成果匹配状态、数值条件分区及期望递推。区别仅在于当前组接受原来的具体技能分配，等价组接受一族合法的技能重新分配。一个成果最多满足一件装备；在同一方式内保留所有可行的用途，直到可以完成该组。

当前组在修正后的成本上选择pool6各件的方式：`C(m,U)`表示方式m完成部件子集U的成果期望，`D(m,S)=min(U⊆S)[C(m,U)+D(m+1,S去掉U)]`。每种方式、每个部件子集只评估一次，最多三种方式、五件防具，不超过93个非空组成本；同一需求多重集也复用计算。非pool6仍独立选择最优方式后相加。当前组及指导JSON保留修正后的当前组次数；实时列表、最终排序和等价路线代表选择优先使用等价组次数。等价次数相同时依次比较当前组次数、逐件次数和待炼／制作件数；未完成或无法估计的等价组排在有估计值的路线之后。卡片中的当前组与等价组数字分别保留，搜索中的配装骨架和逐件目标不变。概率为零时不回退到目标防具冒充宫殿概率，标为暂无法估计。

**等价观星炼化组**固定当前组每件装备的炼化方式，不重新尝试五件全普通或其他方式组合；每件装备的原生技能可扣等级、孔位要求和03限制也完全保留。原来允许破坏王扣≤2级，等价分配仍允许扣≤2级，不会改为≤1级。保留各部位的新增等级数量，按技能的cost及最高等级分组，重新分配具体技能ID，并保持全套每个具体技能的总新增等级。例如A3B3C2的2、2、2、1、1分布在没有额外约束时有19种不同的成果多重集，包含AB、AB、AB、C、C及AA、BB、AB、C、C。实际部位约束可能排除其中一些。

每个新分配检查：原生技能最高等级、不能同时扣增同技能、原生ID占用的五技能容量、03正面上限和记录数下界。原生技能的非正保留下限、各部位原始扩孔需求保持不变；同cost但最高等级不同不会互换。允许珠子与炼化互换时，仅替换单技能、相同等级增量、同cost同最高等级的珠子，检查真实孔等级和库存数量，并通过调整全套具体技能新增需求保持原技能总量。奋斗、业铠【修罗】和狂龙症【翔】没有珠子，不会虚构它们的珠子。已有成品、原生即可使用的新制件、护石和非pool6部件不被改写。

观星期望将合法完整分配组成一个可接受族。同一成果只能用于一个部件，重复需求必须取得足够多个成果；暂不选定成果用途，而是维护所有可行的已匹配部件集合，允许后续重分配。达到族中任意完整分配即完成。状态递推跳过无用成果和重复自环；规模较大时改为固定种子的事件推进估计，并记录数值标准误。它不按游戏实际次数逐次模拟稀有事件。

按本次约定，直接把“至少满足该组合”的查表值当作成果概率，不枚举AAB等额外成果，也不查询或减去技能命中交集。因此**两种观星值都是指定口径下的近似，而非严格互斥概率的精确计算**。同一新增技能构型下，按扩孔、可扣技能总级数、正面条数和总记录数条件划分适用性单元：查询这些数值条件的交叉界限，拆掉包含和交叉重叠，使同一成果只计入一次，同时记录它能够用于哪些部位。此处拆分的是内部概率，不改写任何部位原来的可扣等级或其他限制。使用完整查询精度先差分，再显示三位有效数字；不同技能构型之间不做重叠修正。两组现在使用相同的成果份数口径。等价组保留当前分配作为有效基准；受限枚举或数值估计没有找到更好的分配时保留基准值。

等价计算只使用当前组已选定的逐件方式。按各方式的具体技能总需求分桶后独立计算，允许在不改变方式的前提下交换新增技能，同时避免把不能共同完成全套目标的组拼起来。珠子替换最多24种、技能分配每种最多2048个，触及上限有明确标记。当前组根据修正后的成果期望选择方式；等价组只在固定方式下探索技能分配，不保证所有技能与珠子方案的全局最优。

指导JSON新增`donorProbabilities`、`donorGoal`和`equivalentStargazing`，保留`probabilities`、`individualProbability`及`expectedRolls`的实际防具语义；`stargazingProbability`明确保存宫殿来源值。原有`mode`继续表示当前观星组推荐方式，等价组的方式与示例独立保存，`fixedModes: true`和`modeSearch: "fixed-current-group"`明确标记不改变当前逐件方式；示例附有原生技能保留下限、可扣总级数和记录限制，便于核对。`stargazingModel: "palace-current-group-multiplicity-v2"`标记统一后的计数口径。护石获得次数依旧不计入。

## 候选路线的搜索

“保留成品”和“概率目标”作为确定的最低能力候选，重新选择五个部位、已有或指定护石及珠子。初始目标统一为逐件次数之和：已有成品／原生可用新制件为0，待炼目标为`1 / max(各允许方式的命中概率)`。这个模型不使用观星边际成本、共同方式偏好或跨部位概率联动，也不增加单件最高净技能cost惩罚。

得到候选后，优先围绕较难部位提出同部位换防具、转移一级技能、转移一个珠子所需孔位的有限邻域；新增单件条件查到真实概率后再进入同一个逐件目标。整套约束重新检查技能、实际护石、珠子数量和孔位容量。新候选能力加入时重建模型，并尝试用之前逐件最优解热启动；能力集合不变时，枚举备选路线只追加排除行，复用同一求解器。观星方式分配仅评价完整可行路线，并用于最终展示排序。保留已找到的好路线，不因后续探索得到更差路线而替换。

## 等价路线合并

只对已完成校验的输出路线归一化，不删除内部能力候选，不对求解模型强行加入技能互换约束。每个部位保留防具型号、制作／保留／重炼来源、库存引用及原生技能的具体ID和保留下限；非原生新增技能按cost、最高等级、不同技能的数量及各自等级构成多重集。孔位下限转换为达到该条件所需的最少扩孔量，消除原生4-4装备上的“至少4-2”与“至少4-4”等冗余写法。03记录限制、允许方式及完整概率向量也必须相同。

整套武器、所用护石及已有库存引用（如有）、保障技能列表（含额外技能，等级截断到游戏技能上限）一致后，就把上述单件形状相同的路线合并。珠子种类、数量组合及具体插法不再单独占用路线名额；保留代表的完整原始珠子组合与插法，不拼接不同候选。每个进入去重的候选仍须通过孔位、技能和本次库存数量约束。不会仅因显示次数四舍五入后相同而合并。代表方案优先保留成本更低的完整可行解；成本相同时保留孔位下限更完整的写法。代表更换时实时列表替换同一张卡，保留展开状态；指导JSON仍保存该代表的具体技能位置、珠子插法及原路线ID，并附加`equivalenceKey`。

去重在展示条数限制之前执行。若重复导致路线不足，备选枚举可在剩余时限内继续，最多160次；仍是有限搜索，可能达不到指定条数。内部候选及搜索锚点继续保留具体技能分布，供后续重组使用。

### 相同观星期望仍保留独立路线的情况

路线去重与等价观星评估采用不同的等价关系。去重比较的是每件装备的具体命中条件及实际防具概率；等价观星则在固定炼化方式、原生技能可扣等级、孔位要求和03上限的前提下，接受新增技能的多种合法分配。因此，两套路线可能对应相同的等价观星分配族，同时拥有相同的当前组和等价组次数，仍然分别展示。次数相同（包括未四舍五入的数值相同）不是额外的合并依据。

例如其他部位、护石和约束相同时，以下两种分配保留为两条路线：

| 部位 | 分配一 | 分配二 |
| --- | --- | --- |
| 原初铠甲 | 新增狂龙症【翔】＋1 | 新增奋斗＋1 |
| 久爱腰甲 | 新增奋斗＋1 | 原生狂龙症【翔】由Lv1升到Lv2 |

久爱腰甲原生带有狂龙症【翔】Lv1。分配一要求保留该原生等级，再增加非原生的奋斗；分配二要求将该原生技能增加一级。`routeEquivalenceKey`保留原生技能的具体ID及相对增减下限、非原生新增技能的分组结构，以及每件实际防具的完整概率向量，所以不会将这两种逐件条件归为同一个合并键。原生升级与非原生新增在实际防具上可能有不同命中概率，逐件炼化次数也可能不同。

观星使用统一的公会宫殿护腿参考概率。上述新增技能允许合法互换时，两套路线的等价观星评估可以接受同一族成果分配，因而得到相同的观星期望；这不改变逐件条件本身的区别。

当前约定保留这类路线，不按整套等价观星分配族进一步合并。既有的逐件条件合并规则、珠子组合不独占路线名额的规则仍然适用。等价组次数相同时，再按当前组次数、逐件次数等指标排序，方便同时参考观星规划与逐件手炼成本。

成品及直接可用的原生新制防具为0次。重炼库存成品不能因为原生参数满足目标就假定可以免费恢复；需要抽选时仍计算成功概率和至少一次抽选。这是在已生成的充分能力条件内进行有限搜索，不是所有装备组合的全局最优证明。抽到实际结果后更新库存、重新规划，可能节省后续抽选。当前次数按新推进的随机位置计算，不包含读档后重复推表的操作次数，也不预测存档中的具体随机位置。

## 概率数据

主概率表保留1,636个防具输入类、累计19.35亿次模拟；另有宫殿护腿三种方式各1,000万次的观星专用表（每种保留原200万次前缀，本次实际新增2,400万次）。观星表与主表不是独立样本，不能把两者样本数相加估计误差。pool6的294类和pool13的7类均达到每类200万次，其余池保持原有50万～200万次；涵盖普通、技能特化、插槽特化，表13只支持普通。相同cost、最高等级和原生等级结构使用匿名分拆保存，查询具体技能时按不放回分配换算。不是把词条成功率独立相乘。

概率只统计技能、孔位及记录限制，防御、耐性不作为额外命中条件。示例的防御、耐性条目不是玩家必须逐条复现的目标。概率未观察到命中时不据此判为理论不可能，但当前路线库不会把它当成有可靠次数估计的候选。

每个部位显示样本数、有效命中、标准误和稀疏标记。预计次数是有限样本下的估计均值，不是保底次数，也不预测存档下一次的随机数。新护石的未核实抽选细节不影响现有护石作为确定输入使用。

网页与离线版共用紧凑概率表：共享原生/新增技能构型字典，使用差分整数编码及gzip压缩，再按所需类加载、解压并保留有限缓存。主表加观星专用表运行数据约15.11 MB。全部7,841,602条联合构型及整数计数逐条核对一致，没有删除低概率构型。查询概率和标准误最多保留三位有效数字，小概率不会因小数位截断而归零。线上首次读取索引会重新验证浏览器缓存，概率文件请求附带由整份计数生成的数据集标识，避免混用增样前的数据。同一输入类内，按原生技能类型与等级、同cost及最高等级的新增技能需求、实际扩孔阈值及记录限制归一化查询键，复用严格等价的查询；不是把不同原生结构只按pool合并。

单文件离线版嵌入相同压缩数据，可直接打开。完整累计计数、样本段种子、规则指纹及模拟程序单独保留在研究目录，后续增样后可重新生成运行数据；这些文件不进入用户包。源码维护者可运行 `node prepare_probability.cjs` 重新编码，同时逐类校验计数一致。

## 库存与导出

仅重炼库存型号时会注明对应箱位。网页没有向游戏写入或修改装备的接口，玩家需要在游戏中自己操作；重炼前注意是否要保留当前成品。已有防具允许单条和累计扩孔溢出，保留全部记录、费用，最终孔位截断到4-4-4。

珠子数量沿用库存快照的保守计数口径；不重复累加已镶珠子。选择“允许另行制作所需珠子”后不限制普通珠子数量，但不计算制作素材。

“导出指导JSON”保存本次条件、库存标识和路线信息，用于备查；它不是配装管理器Mod文件。实际炼化完成后，重新导出库存，并在已有模式或手炼指导中重新计算。
