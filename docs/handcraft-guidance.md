# 手炼指导（0.8.20）

手炼与配装工房共享01～03条件。实际护石或03明确指定的合法护石作为前提；护石获得次数不计入。已有防具与珠子沿用库存约束；允许制作珠子时不计算素材。

## 搜索目标

第一阶段使用固定权重：非成品部件15、新增技能cost加6、删除原生技能每级−1、扩孔点数乘10。目标函数为 `15N + Σ(cost+6)A − D + 10G`（0.8.15起使用10G，0.8.16起使用−1D）。最多8套骨架、最多8秒；此区段没有引入观星计算。初始骨架使用普通防御兜底校验；0.8.20起同时检查兜底前后防御抵消，自由段采用负防御在前、正防御可重排的简化检查，并优先重选可调整的防御数值，无法修复才跳过具体构型。

第二阶段直接以完整等价组期望为主要目标：完整候选先经实际技能、护石、珠子和孔位校验，再按等价成本接受、保留、选择锚点继续扩展。线性模型仅负责生成可行提案，不把非线性等价成本伪装成五个独立价格，也不是搜索结束后才重排逐件解。等价值相同时再比较原路线逐件成本。

骨架部件即使未进入当前最佳组合，也可以产生降低技能或孔位下限的候选。原目标未观察到命中不代表不能放宽。支持换防具、技能与孔位需求转移，以及两部位同时交换技能或孔位要求。不同操作交替使用查询名额。预算压力仅轻微调整尝试顺序；按实际删技能词条返还预算，覆盖缺口后饱和，不进入等价正式目标。

等价分支不再使用“单件逐件成本高于整套逐件最好值”的筛选。它使用现有有限查表模型内的乐观下界：对每个部位的合法可接受目标，累加命中概率作为并集上界，再乐观选择最快方式，取等待下界；所有部位取最大值。仅在此下界也不能改善现有等价值时跳过完整评估。

## 三种次数与方式

原路线逐件次数仍使用实际防具表，各件取允许方式中最大的命中概率，计算倒数之和。已有成品与原生可用新制件为0。重炼现有成品不能假定免费恢复。

当前观星组按实际成果份数计算，固定原路线具体技能分配，单独选择自己的方式。0.8.19起，pool6默认按允许扣技能的位置权重查询公会宫殿护腿词条，并检查全部正向技能在目标上的合法性；不计算扣后补回，也不把目标最终孔位直接套在宫殿护腿上。非pool6仍独立计算。一个成果只能用于一个部件，重复需求必须取得足够份数。

等价组保留每件各类cost与最高等级的新增等级数量、孔位要求、原生技能保留下限、可扣等级和03限制，重新分配具体技能ID。检查原生等级上限、不能同时扣增同技能、原生ID占用的五技能容量，以及正面和总记录数。珠子交换只接受同cost、同最高等级、同等级增量的单技能珠子，仍检查实际孔位和库存。奋斗、业铠、翔没有珠子，不会虚构珠子。

0.8.13的等价组在允许方式中有预算地搜索自己的方式，不再固定当前组的方式。当前组指标与方式单独保留。界面摘要显示等价组的一种合法示例与对应方式；逐件数字和详细概率仍指原路线，两者不保证同一技能分配。JSON的searchObjective标记新主目标，equivalentStargazing.assignment与example给出等价方案，fixedModes为false，modeSearch为equivalent-objective-coordinate。

## 单件观星的位置权重与目标合法性（0.8.19）

默认不再计算扣后补回。对宫殿表中满足新增技能、原始扩孔及记录限制的源记录，按源最终保留的扣除总级数k乘位置权重w_k。设目标有n个原生技能，每个原生技能允许扣除c_i级，权重为所有 `Σd_i=k、0≤d_i≤c_i` 的分配之和：`w_k=Σ k!/(n^k×∏d_i!)`。上限不超过原有等级，不根据宫殿具体扣了哪个技能条件化。

三技能且只有一个技能可扣2级时，概率为 `p0+p1/3+p2/9`；两技能、四技能分别使用对应原生数量。多项可扣时按各项独立上限合计，不能把上限简单相加后只乘一个幂次。不允许扣技能时只接受源k=0记录，不再把“源扣1级并同时新增同技能”当作不扣。

全部源正向技能都检查目标容量。目标已有技能不占新种类；同一技能新增多级只占一种。额外新技能在剩余容量内可接受，超过五种时排除。目标原生ID即使可扣光仍保留容量。由于不再考虑扣后补回，原生技能新增上限按 `最高等级−原有等级` 检查，不借扣除增加等级空间；正面和总记录上限直接检查源记录，不扣除所谓抵消对数。

匿名查询仍使用同cost、最高等级类别内的不放回联合标签分配，区分额外技能恰为目标已有与属于新种类，不独立相乘。模型可能忽略实际可通过补回满足的成果，这是本次明确采用的简化；单件原始防具概率和模拟样本不变。

当前组、等价组、候选定价和下界使用同一默认口径。联合观星继续忽略不同装备实际扣除位置可能不兼容的相关性；对同一匿名源记录采用各单件加权边际命中的最小值，不额外乘跨装备位置交集。源中已取消、未保留的抽选历史仍不重放。

## 查询缓存与性能

0.8.18引入的预编译区间匹配、源正向向量复用及完整技能关联缓存继续保留；0.8.19默认只编译一次固定目标条件，不再枚举扣除分配与补回区间。结果键保留位置权重、原生/非原生类别、等级、必要技能重叠、容量和记录上限，并与旧逆推口径隔离。实测和验证见[0.8.19记录](performance-0819.md)。

## 概率口径和搜索限制

按既定口径直接使用“至少满足某技能组合”的查表概率，不枚举额外AAB等成果，也不扣除不同技能构型间的交集；只对同构型的扩孔、可扣等级、记录上限等数值适用条件分区，避免重复计入同一数值事件。当前和等价组都属于这一口径下的近似，不是游戏真实互斥概率的精确计算。

每条路线默认最多14个相邻方式尝试，并受单条及整轮时限约束。珠子替换最多24种、每种技能分配最多2048个，达到上限会标记。规模较大时按固定种子事件推进估计，保留标准误。状态成本、概率和路线结果可以复用缓存；超时不当作理论不可能，也不永久缓存为无解。搜索有候选数、邻域与时间上限，不构成全局最优证明。

## 等价组归一与展示

0.8.14起，第二阶段、实时卡片与最终结果共用等价组身份，同一组仅占一个展示名额，先去重再限制条数。内部能力候选、原路线及搜索锚点仍保留具体技能分布，不因展示合并而删除可探索分支。代表路线先比较等价期望，再比较原路线逐件期望，保留代表完整的技能、珠子插法与原路线当前观星指标，不拼接不同路线的数据。

组身份保留武器、库存及护石引用、目标与保障技能、各部位防具型号、制作／重炼／保留来源、原生技能保留下限、最少原始扩孔量、可扣总等级和记录上限。pool6部件的新增技能按cost与最高等级统计各部位等级配额；各合法珠子方案对应的具名技能总量与这些配额共同确定完整可接受分配族。原路线里A+B与A+2、不同技能位置及实际防具概率不再单独阻止同组合并。其他pool与完成件仍保持具体条件。联合方式优化的组身份包含允许方式，不依赖本次有限方式搜索选中的方式。

珠子方案枚举若达到预算，只在完整候选输入域也一致时确认同组，不能拿相同的部分枚举结果当作完整等价证明。技能分配枚举截断时保留其完整数学定义（配额、原生限制与具名总量）。预计次数相同、显示示例相同均不是组身份。不同限制、来源、库存箱位或可接受分配族仍分别展示。

等价摘要的孔位使用原生孔位经过最少扩孔后的实际下限。例如脉动钢龙强力321与久爱腰甲420均在+2时成为431；原目标≥331与≥431统一展示≥431。摘要显示等价组示例，原路线逐件／当前观星数字与方式明确标注原路线，详情保留该代表的实际技能条件和概率。JSON保留原路线equivalenceKey，并在equivalentStargazing.groupKey中保存完整组身份。

候选规模选项为30、60、90、120、150，默认30。保持原有第一阶段目标函数与时限；规模参数继续控制后续候选和邻域探索，不承诺恰好生成该数量的第一阶段骨架。

## 概率数据

主概率表保留1,636个防具输入类、累计19.35亿次模拟；另有宫殿护腿三种方式各1,000万次的观星专用表（每种保留原200万次前缀，本次实际新增2,400万次）。观星表与主表不是独立样本，不能把两者样本数相加估计误差。pool6的294类和pool13的7类均达到每类200万次，其余池保持原有50万～200万次；涵盖普通、技能特化、插槽特化，表13只支持普通。相同cost、最高等级和原生等级结构使用匿名分拆保存，查询具体技能时按不放回分配换算。不是把词条成功率独立相乘。

概率只统计技能、孔位及记录限制，防御、耐性不作为额外命中条件。示例的防御、耐性条目不是玩家必须逐条复现的目标。概率未观察到命中时不据此判为理论不可能，但当前路线库不会把它当成有可靠次数估计的候选。

每个部位显示样本数、有效命中、标准误和稀疏标记。预计次数是有限样本下的估计均值，不是保底次数，也不预测存档下一次的随机数。新护石的未核实抽选细节不影响现有护石作为确定输入使用。

网页与离线版共用紧凑概率表：共享原生/新增技能构型字典，使用差分整数编码及gzip压缩，再按所需类加载、解压并保留有限缓存。主表加观星专用表运行数据约15.11 MB。全部7,841,602条联合构型及整数计数逐条核对一致，没有删除低概率构型。查询概率和标准误最多保留三位有效数字，小概率不会因小数位截断而归零。线上首次读取索引会重新验证浏览器缓存，概率文件请求附带由整份计数生成的数据集标识，避免混用增样前的数据。同一输入类内，按原生技能类型与等级、同cost及最高等级的新增技能需求、实际扩孔阈值及记录限制归一化查询键，复用严格等价的查询；不是把不同原生结构只按pool合并。

单文件离线版嵌入相同压缩数据，可直接打开。完整累计计数、样本段种子、规则指纹及模拟程序单独保留在研究目录，后续增样后可重新生成运行数据；这些文件不进入用户包。源码维护者可运行 `node prepare_probability.cjs` 重新编码，同时逐类校验计数一致。

## 库存与导出

仅重炼库存型号时会注明对应箱位。网页没有向游戏写入或修改装备的接口，玩家需要在游戏中自己操作；重炼前注意是否要保留当前成品。已有防具允许单条和累计扩孔溢出，保留全部记录、费用，最终孔位截断到4-4-4。

珠子数量沿用库存快照的保守计数口径；不重复累加已镶珠子。选择“允许另行制作所需珠子”后不限制普通珠子数量，但不计算制作素材。

“导出指导JSON”保存本次条件、库存标识和路线信息，用于备查；它不是配装管理器Mod文件。实际炼化完成后，重新导出库存，并在已有模式或手炼指导中重新计算。
