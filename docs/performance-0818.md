# 0.8.18观星查询性能与正确性对照

基准0.8.17提交`a53456a`，优化提交`1f295f0`与`4034dd9`。概率模型、样本、第一阶段权重及联合观星算法保持不变。完整基准脚本和原始统计保存在Git仓库的`benchmarks/performance-0817-opt/`。

## 对照方式

`measure.cjs`用Node的同一执行域加载原版和优化版概率模块。固定查询先解码宫殿三种方式的相同样本，再预热，交错顺序测量7轮；固定路线评估各5轮。表中取中位数。完整搜索顺序独立启动，使用截图弓、狂化2业铠1s411、五件固定型号、全部珠子及三种炼化方式，60秒/30候选。WASM初始化不计入搜索时间。时间不代表用户手机或浏览器实测。

## 优化内容

1. 分配计划按目标、扣技能总级数和补回要求缓存，目标序列化移出逐源记录循环。
2. 匹配条件预排序、预编译；源记录的正技能向量及类型数量在单次查询内复用。跨查询共享有界的区间匹配器，向量缓存使用内容键，不跨查询保留可变输入的旧内容。
3. 结果缓存按完整技能关联关系归一化：只交换源端同一原生/非原生类别、同cost和等级上限的技能名称，并保留每个目标的原生等级、净变化下限、必要词条重合关系、容量和记录限制。源原生与非原生、共同技能与不同技能不能混用。

两边完整搜索的最佳等价观星期望均为21,659.732828072236次。优化后返回2个不同等价组；原版在时间限制内返回5个组，其中部分方案遭到单路线预算截断。返回路线数不能单独用来衡量搜索质量。限时搜索的轨迹会随运行速度变化，固定查询/路线对照才用于证明概率不变。

仅第一、二项内核优化（Stage A）时，完整搜索14.29秒、首次2.91秒、唯一查询3,840次。再加结果键归一化（Stage B）后为上表12.28秒、2.34秒、1,496次。冰双仍受联合组状态推进及固定4096次事件估计的开销影响；本轮未改动它们。

## 正确性

- 122件pool6防具、三种方式、不同孔位、技能重复/不同、扣除允许量、原生补回、完整/部分词条校验及联合目标，共3,615项直接查询，对原版逐项完整JSON严格相等，包括概率、标准误、命中统计和模型标识。
- 同一批查询经实际结果缓存按正序与倒序执行，再逐项与原版核对。3,585个归一键，7,230次调用中3,645次缓存命中，全部严格相等。
- 固定弓和冰双路线的当前组及等价组数值各重复5轮，优化前后保持相同。
- 专门覆盖可变源向量、源技能总体变化、源原生/非原生区别、全局重命名、必要技能与原生技能重叠、联合目标共享名称。

完整测试共347项：344通过、0失败、3项既有跳过。离线HTML已从优化源码重建，用于验证嵌入Worker兼容性；此记录来自发布前的本地实验；正式发布包另行验证。
